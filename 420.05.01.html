05.01 客戶入口 公告與多語

顧客第一次求助時，最先遇到的通常不是 Jira 的工作項目，而是一個服務入口。入口名稱不清楚、分類太多、公告過期或語言混雜，都會讓顧客在真正提出需求前就卡住。本課教你建立清楚的 portal，並理解哪些設定屬於單一服務團隊、哪些屬於更上層的 help center。

基本詞彙與管理邊界

Portal（客戶入口）是服務專案提供的請求與自助入口；Help center（說明中心）可集合多個服務入口與說明內容。Request type（請求類型）是一種可提出的需求；portal group（入口群組）把這些需求排成顧客好找的分類。Widget（嵌入式小工具）是放在另一個網頁上的求助介面。它是提供服務的管道，不是本教材網站的練習元件。

專案管理員（project admin，新版稱 space admin）管理該服務專案（新版 service space）的 portal；Jira admin 管理 help center 等較大範圍設定。Agent（服務人員）是否能發公告，則要看管理員有沒有授權。本文以 company-managed 為主，步驟使用目前官方 Cloud 名稱。未在租戶實測，不能把示意畫面當成操作成功證據。

05.01.01 讓顧客知道這個入口服務什麼

到 Space settings → Channels & self service → Portal，設定 Portal name、Introduction text 與 Logo。例如原創的「會議與設備服務」入口，介紹可寫「借用設備、回報會議室問題，以及查詢準備方式」。這比只有部門縮寫更能幫顧客判斷該不該在此求助。S01

Portal logo 出現在顧客入口與相關通知，並不同於內部團隊看到的 space avatar。Portal 的網址、banner、按鈕與連結顏色由所屬 help center 繼承；如果想改這些，應檢查 help center 設定與管理角色，不在單一 portal 一直找不存在的控制項。S01

品牌設定的目的包括辨認來源與降低疑慮，但不能替代安全。即使顏色與公司一致，顧客能否看見內容仍由存取設定決定。練習時只用自製測試圖示與虛構名稱，不上傳真實商標或更改正式入口。

05.01.02 與 05.01.03 公告及公告權限

Announcement（公告）適合讓造訪者先知道共同情況，例如「練習公告：週五下午進行設備盤點，借用回覆可能較慢」。Portal 公告出現在該入口上方，對有該服務專案存取資格的人顯示；help center 公告則在較上層首頁，範圍不同。S02

目前文件的 portal 公告路徑是由 Channels 的 Portal 卡開 View portal，再選 Customize → Manage announcements，填標題與訊息並儲存。要讓 agent 維護公告，由 space admin 到 Space settings → Channels & self service → Portal，在 Announcements 允許 agents 新增公告。S02

把權限給 agent 的好處是服務現場能迅速更新，但設定權限與寫出公告是兩個步驟。允許公告不代表系統會自動生成或自動撤下過期訊息。實務上應寫明影響範圍、替代方式、資訊更新時間及負責人；這是本教材的操作建議，不是額外的 Jira 自動功能。

Help center 公告通常由 Jira admin 管理，也有另一個 help center 層級的 agent 授權設定。不要以為某專案允許 agent 發 portal 公告，就同時讓他能改整個 help center。S02

05.01.04 Widget 是另一條接件路徑

Widget 可以把求助入口嵌進你控制的網站。官方目前要求先有 open portal；若要在 widget 讀取 knowledge base（知識庫）文章，相關 Who can view 必須適合 Anyone 的公開讀取情境。這是重大存取決策，不應為了顯示小工具就把正式內部文章公開。S03

在 Space settings → Channels & self service → Widget，選是否使用 virtual service agent、設定 Default request type，再調整外觀與標準訊息。若出現 request type 不相容，可能是它含有 widget 無法呈現的必填欄位。要回頭檢查資料收集方式，不能只刪掉必要業務資訊以消除錯誤。S03

儲存後的 widget 設定會反映在所有嵌入該 widget 的位置。真正嵌入時，才由獲准的網站維護者取得 Embed code 並放到所控網站。本課不提供或執行嵌入程式碼，也不要求把教材網站接到真實 Jira。受限 request types 不支援 widget，因此要把限制與管道相容性一起檢查。S03S04

05.01.05 Portal groups 讓人找得到合適需求

在 Portal → Portal Groups 建立群組，例如「我要借設備」「設備有問題」。開啟群組，用 Add request form 加入既有 request type，再排序。相同 request type 可在多個群組出現；群組是入口導覽，不是 work type 或獨立工作流程。S05

只設一個群組時，文件指出不會呈現多群組分類；建立兩個以上再驗證導覽。如果把入口從全部群組移除，它仍可能出現在搜尋與 help center topics，因此不能拿群組當權限界線。若目的是讓特定對象才可提出某項服務，要回到 request type Restrictions，而非重命名或藏群組。S05S04

05.01.06 外部資源連結

有些說明已放在公司其他工具，例如公開設備相容性清單。可以到 Space settings → Channels & self service → External resources，新增已核對的連結、資源類型、標題與描述，再按需要排序。這些會以 Related resources 顯示，也可能出現在 help center 搜尋；目前還有數量上限，新增前以實際介面與官方文件核對。S06

新增連結不會把外部文件變成 Confluence 知識庫文章，也不會改變目的地權限。若顧客點進去遇到登入或拒絕存取，應檢查該網站本身的分享設定。練習連結用公開官方文件或明確允許的測試頁面，不將私人文件暴露給顧客。

05.01.07 語言的三個層次

第一層是 agent 的個人應用程式語言。使用 Atlassian 帳號的人可以從 Profile → Manage your account → Account preferences 選 Language；帳號偏好可覆蓋管理員設定的預設介面語言。這是 agent 如何讀 Jira，不代表他翻譯了客戶入口內容。S07

第二層是服務專案的 default language（預設語言）。它是客戶偏好語言未提供或未啟用時的回退。Company-managed 可在 Space settings → Language support 審查語言翻譯、啟用後選 Change default language。若 Jira site 的預設語言也要變更，則是 Jira admin 的管理範圍，不能混為單一入口設定。S08S09

第三層是客戶自己的語言偏好。客戶可在 help center 的頭像 → Profile → Edit account preferences 選語言。只有該服務已提供並啟用的語言，才能帶來相應入口體驗；沒有提供時會用服務預設語言。測試至少準備「有提供的語言」「尚未提供的語言」兩種情境。S08S10

05.01.08 翻譯要覆蓋整條求助旅程

Language support 可新增額外語言。新增後預設不供客戶使用，先翻譯與審查，再開啟 Available to customers。系統既有字詞、你自行寫的內容及 Forms 的翻譯不是同一件事，不能因為選了語言就宣告整個服務已完成在地化。S09

逐項檢查 portal 名稱與介紹、公告、request type 名稱及說明、欄位名稱與提示、customer notifications（客戶通知），以及 email templates（電子郵件範本）。到 Language support 選語言，從各內容分類檢查預設文字與翻譯對照，修正缺漏與過期標記後儲存。S11

Email templates 要在該語言的 Email templates 分類單獨處理；修改原文之後，不能假設每種語言的 email template 會自動更新。官方也列出方案與試用期限制，若 Free 或特定方案不能編輯，先記錄限制，不教學員升級付費以便繼續練習。S12

本教材的繁體中文是臺灣用語。介面若有 Chinese (Traditional) 選項可作練習，但選單上的語言名稱與所有細節翻譯仍以租戶為準；課文本身不把所有英文產品名強行中文化，board 與 Kanban 保留英文。

隔離練習 驗證顧客看到的一整套服務

前提：獲准的隔離專案、虛構測試帳號、沒有正式使用者。若要試 open portal、Anyone 知識庫或對外嵌入，必須另有明確授權與完全公開的測試資料；沒有就僅做設定盤點，不變更存取。

  1. 記錄現有 portal 與 help center 的邊界，將示範 portal 改為「練習：會議與設備服務」，加入自製圖示與介紹。
  2. 建立兩個群組，各放適合的 request types。以客戶身分確認名稱能幫助選對入口。
  3. 新增一則清楚標為測試的公告，確認只出現在預期 portal。由管理員批准測試 agent 發公告後，讓 agent 修改它，觀察授權效果。
  4. 新增一個公開官方說明連結，檢查 Related resources 的標題、描述、順序與點入權限。
  5. 新增第二語言，補齊入口、request type、通知與範本翻譯；先預覽再啟用。變更一段原文，回頭看翻譯是否要重新審查。
  6. 用不同偏好語言的測試顧客查看入口。用 agent 帳號調整其個人語言，再比較：agent 介面語言不等於客戶內容已翻譯。
  7. 若沒有 widget 公開存取授權，只完成紙上配置：列出 open portal、文章公開範圍、default request type、必填欄位及所有嵌入位置。不要為了完成作業而啟用公開存取。

摘要

Portal 配置要同時照顧品牌辨識、清楚導覽、及時公告與可用語言。Help center、portal、widget 與外部資源各有管理和存取範圍；用顧客身分測試整段路徑。

常見陷阱

  • 將 portal logo 與 space avatar 混用
  • 把某 portal 的公告權限理解成所有 help center 管理權
  • 為了 widget 任意公開內部知識庫
  • 誤認新增語言或改原文後，所有自訂內容與 email templates 已自動翻好

觀念釐清

翻譯內容、啟用語言、設定預設語言與使用者個人偏好是四個不同動作。正確驗證需要觀察客戶實際拿到什麼，而不只是設定列表上多了一個語言。
