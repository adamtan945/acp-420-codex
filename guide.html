從零開始 先看懂Jira Service Management

JSM把顧客求助、團隊處理與服務改善連在一起。先辨識角色與資料，再學入口、流程、計時、知識庫、報表與自動化。Cloud和company-managed是本教材的主要邊界，所有操作先確認隔離環境。

01.01 身分、角色與多層權限

先分清「帳號能使用哪個產品」、「人在專案裡扮演什麼角色」與「這張案件跟他有什麼關係」。再依實際動作檢查產品、全域、專案、客戶及知識庫權限，必要時加查案件安全性。

01.02 客戶、組織與請求分享

先決定網站註冊與登入，再設定服務專案的請求管道與分享；每一步都用不同測試帳號驗證。客戶與組織 detail fields 是背景資料，定義可跨專案影響多人。

01.03 服務團隊、指派與存取排錯

成員管理以角色為中心，產品授權另行核對；預設指派要有可被指派的人；排錯先分清建立時與後續變更，再逐層驗證存取。

02.01 佇列配置與 JQL 排錯

Queue 的設計由工作決策出發，再決定集合、欄位與排序。建立後用已知工單做正反向驗證，並把 Priority groups 與工單 Priority 分開理解。

02.02 Configure SLAs 設定服務等級協議

先說清楚適用對象、起點、停點、排除時段及時間目標，再做設定。驗證時，用工作項目歷程和行事曆逐段計算，並確認採到第一個符合的 goal。不要只看碼表顏色、狀態名稱或設定頁有沒有按儲存。

02.03 功能開關與 ITSM 工作類別

功能選擇從工作目的出發，並核對方案、專案類型與角色。開關只啟用能力或入口，真正可用仍需後續配置和驗證。

02.04 值班排程、路由與升級

Schedule 回答何時由誰值班，rotation 建立週期，override 處理暫時例外，routing 挑路徑，escalation 處理沒人接或尚未關閉的後續，alert policy 調整警示建立時的屬性。

03.01 在請求中使用 Assets

用 schema→type→object→attribute 辨識資料層級，再用 Assets 自訂欄位把請求連到具體物件。分清 JQL 查工單、AQL 查物件，以及 request form 和 Forms 的儲存行為。

03.02 服務目錄、責任角色與服務分級

服務目錄讓事件與變更取得共同脈絡。分清服務本身、工單關聯、依賴方向、Tier 和各責任；讓政策成真仍需適當 workflow、automation 與 alert 配置。

03.03 產品與支援資格

先辨識 JSM／CSM 環境，再建立產品、授予個人或組織資格，最後在請求上選取並顯示資格。必填的效果必須用有資格、無資格與另一產品資格三種案例驗證。

04.01 請求類型與欄位呈現

先辨識 request type、work type、workflow 與 screen 的責任，再設定客戶欄位及 agent 布局。Portal groups 幫顧客找入口；Restrictions 控制誰能提出該類型請求；既有工單閱讀權限另行管理。

04.02 表單 條件邏輯與欄位連結

先設計問題及條件區段，再決定需要連到 Jira 的核心資料。表單位置、可見性、語言與提交後偏好分開檢查，才能同時滿足顧客填寫與團隊處理需求。

04.03 電子郵件請求管道

電子郵件接件需同時配置連線、合適的 request type 與寄件過濾。排錯先找處理記錄與欄位條件，再檢查顯示工單的 queue；停用管道前要確認替代服務方式。

04.04 工作流程 入口轉換與核准

先追查 request type 的底層 workflow，再設計核准來源與決策出口。固定核准人適合穩定責任；顧客選人適合案件間差異。Portal transition 提供自助動作，必須檢查是否繞過必要流程。

05.01 客戶入口 公告與多語

Portal 配置要同時照顧品牌辨識、清楚導覽、及時公告與可用語言。Help center、portal、widget 與外部資源各有管理和存取範圍；用顧客身分測試整段路徑。

05.02 Virtual service agent 與知識庫回答

Virtual service agent 結合意圖辨識、對話流程、知識回答與真人接手。先確認方案、AI 與知識庫前提，再驗證預設 request type；最後用對話方式與結果一起評估成效。

05.03 通知與共用回覆

先分辨事件、收件角色與通知路徑，再修改內容或追查寄送。Shared canned responses 協助人工回覆的一致性；它與自動通知分屬不同機制。

06.01 知識庫連線與權限

先連上正確 Confluence 來源，再逐層確認站點允許模式、來源檢視與編輯設定、以及 Confluence 限制。用真正的客戶角色測試，並把讀與寫分開記錄。

06.02 文章建議與內容組織

用 request type 決定在哪個求助情境提供建議，用 labels 限定相關主題，再以實際顧客身分測試。文章內容品質、可見權限、來源架構與搜尋相關性都影響是否真正幫助顧客。

07.01 用 JQL 找到真正需要處理的請求

JQL先界定資料範圍，再選正確欄位、運算子與函式。核准、SLA最近週期、SLA歷史、產品資格是不同概念。保存filter保留查詢，分享filter不會取代工單權限。AI查詢要驗證語意與實際結果。

07.02 讓報表回答服務改善問題

先定問題與資料範圍，再建立series和report，最後用dashboard組織閱讀。CSAT、SLA和知識庫報表各量不同事情。用報表找設定問題與改善假說，不把同時變化當因果。

08.01 先選對自動化需求 再設定規則

先把事件、範圍、條件、動作、責任人和驗證寫清楚。欄位／指派、SLA提醒、通知、Assets狀態連動各有不同目的。自動化應符合服務政策，不能只讓管理員覺得步驟少。

08.02 從事件到結果 建立JSM自動化規則

選事件、加條件、對正確上下文做動作；依需求使用branch。JSM專有元件涉及核准、SLA、Assets與Forms，scope並非全部相同。Smart values要核對型別和上下文。範本與AI都要審查，啟用後用audit確認。

08.03 用紀錄找出自動化為什麼沒照預期工作

先記錄預期與實際差異，再查scope、事件、條件、動作及actor。audit找單次原因，Performance Insights看整體量與耗時。owner負責維護，actor執行；交接與限制都要看具體配置。
