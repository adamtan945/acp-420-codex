04.02 表單 條件邏輯與欄位連結

假設同仁要申請會議設備。線上會議要問會議連結，實體會議要問會議室；兩種情況都要問活動日期。把所有問題排在一起會讓人漏填或誤填。Forms（表單）可以把說明、資料輸入與條件式區段組合起來，同時避免每個臨時問題都變成一個全站 Jira custom field（自訂欄位）。

本課教你設計這份表單，以及判斷哪些資料必須連回 Jira 才能供一般查詢與報表使用。

零基礎先備

服務專案（service project，新版稱 service space）管理一組服務請求；request type（請求類型）是顧客選擇的入口；工作項目（work item，考綱稱 issue）是送出後團隊處理的紀錄。Request form 是入口上的整體填寫畫面；

本課的 Form 是可附加的表單功能，不是同一詞的任意替換。Form field 儲存表單中的回答；Jira field 是 Jira 系統或自訂欄位，可用於一般 JQL（Jira Query Language，查詢語言）、報表與工作流程。S01

建立、編輯、連結表單通常需要 Jira admin 或 space admin；顧客是否可看到或編輯表單，還取決於表單位置、可見性與狀態。課文以獲准的隔離 company-managed 示範專案為操作前提。表單功能也有 team-managed 適用情況，但不把兩種專案的全部設定視為相同。

04.02.01 建立有結構的表單

到 Space settings → Request management → Forms，選擇 Blank form（空白表單）或合適範本。空白適合已知道要問什麼的流程；範本適合先理解常見結構，再刪掉與自己需求無關的題目。部分目前介面會先要求選擇 work type，依實際畫面與適用文件操作。

S02

在本例，先寫一句用途：「這張表單用來安排會議設備」。以項目清單交代準備事項，再加入短表格比較「線上」「實體」的準備資料；引用區塊可提醒「不要填入會議密碼」。表格、引用、標題與欄位各有用途：說明文字不會自動變成可查詢的欄位，漂亮的版面也不會替代驗證規則。

桌面雙欄 layout 的內容到手機仍應能按合理順序閱讀。

新增活動方式、活動日期與補充說明等欄位，調整標籤、說明、選項、預設回答與排列順序，再使用 Preview 檢查。先確認每題必要性，才能決定必填，而不是把範本所有欄位都照單全收。S02

04.02.02 讓 section 隨回答顯示

Section（區段）是一組一起顯示或隱藏的內容。Conditional logic（條件邏輯）以較前面的選擇答案決定區段是否出現，例如活動方式等於「實體」，才顯示「會議室」區段。這是顯示邏輯，並不等於另建 request type 或修改工作流程。

在 form builder 選取區段，再設定 Show Section／Create logic，選擇判斷欄位、運算子與答案。現行文件以單選、複選、下拉等選擇欄位作為條件來源，並說明 AND 要同時成立、OR 則容許另一組條件成立。

務必用 Preview 各走一次「線上」「實體」及改回原答案的路徑。S02

不要把區段放進表格或 layout 的內部後，就假定顯示結構一定正常；官方明示這可能破壞表單結構。必填與條件區段也要謹慎處理：目前 linked-field 文件指出，標成 required 的表單欄位不能放在 conditional section，包括連到 Summary 的必填欄位。

本教材不教「把底層必填藏掉就能跳過」。若租戶提供不同能力，應在隔離環境測試並確認版本，不用猜測補上規則。S02S03

04.02.03 預設回答不等於寫入 Jira 欄位

表單上看見文字不等於 Jira 欄位已有值。

Default response（預設回答）讓某個欄位開啟時先有內容。例如活動方式預選「實體」。它是填寫起點，不是證明每場活動都實體，也不等於限制顧客只能選這個答案。選取欄位後在其設定面板中設定此欄位支援的預設值，再預覽「未修改」「改成另一答案」兩條路徑。不同欄位類型支援選項不同；

本次未在租戶核對各型別的 default response 控制項，沒有看到時先查該型別的實際功能，不新增虛構按鈕。

如果團隊要在 queue（佇列）篩選「下週的活動」，日期應連到適合的 Jira 日期欄位。在表單編輯器選取欄位，於 Linked Jira field 選擇對應 Jira field，再儲存。Linked（連結）讓表單收集的資料可進入 Jira 一般資料處理；

單純把欄位命名為「活動日期」並不會自動建立同名 Jira 欄位。S01S03

連結有幾個約束：兩邊型別要相容；同一份 form 不能讓多個欄位連到同一個 Jira field；同一 Jira field 不應同時在 request form 與附加 form 中重複出現。若連結時移除了原 request form 的欄位，是避免顧客填兩份可能矛盾的答案。

完成後要看實際工作項目的 Jira field，而不是只看表單有字就說連結成功。S03

未連結 form field 仍可提供閱讀脈絡，並不因此無用。要注意目前 Forms 另有專用 smart values 等整合能力；「未連結」不宜誇大成任何 automation 都絕對無法讀取。

ACP-420 此處的基本判斷是：若需要常規 JQL、報表或 Jira 欄位流程，先安排合適的 linked Jira field。專用 Forms smart values 的詳細語法屬於本節延伸，不替代欄位設計。S01S10

04.02.04 翻譯是內容與供應狀態兩件事

在 Form 的 Translate 分頁新增語言，逐項翻譯標題、題目、說明、選項與可翻譯的內容，檢查缺漏標記。完成後打開 Available to customers；如果該語言尚未在服務專案 Language support 啟用，portal 仍可能無法提供該語言。

客戶偏好語言沒有翻譯時，會回退到原表單的 primary language。S04

Settings 中只調整驗證訊息或按鈕使用的 Language，不代表你撰寫的問題會自動翻譯。另需知道兩個目前限制：連結 Jira fields 或 data connections 的 choice fields 不能假設支援翻譯；

agent 把表單附加到既有請求時，有文件列出的已知語言限制，可能採 agent 的語言。這些都應列入測試，不能承諾所有位置都依客戶偏好自動切換。S04S05

04.02.05 表單附在哪裡決定何時出現

要讓客戶一開始就填，到 Request types 選入口，於 Request form 底端選 Attach form，挑既有表單或從範本建立。也可以從 form builder 的 Settings → Attach to request types 選擇入口並儲存。

這是入口配置：之後使用該入口提出請求的客戶會看到表單。S06

若要案件進到特定階段才補充資料，則是將 form 附到既有 work item。Agent 可在工作項目使用 Attach form；這種手動加入的表單預設為 Internal，若要客戶填寫，需檢查是否要改為 External。

Automation 的 Attach forms 動作同樣是附到工作項目，可設定可見性；目前此動作限專案範圍，不能在 global flow 中任意使用。S07S08

所以考綱寫「手動或 automation 附加 forms」時，要說清楚入口設定與執行時附加是不同層次。不要把 Attach forms 動作解釋為每次執行都修改 request type 的設計。

04.02.06 可分享的連結仍有使用身分限制

在 form 的 Settings 開啟 Create a shareable link，選定 request type，複製可用連結。General link 可讓有權限的人選擇服務專案、request type 與 form；Direct link 帶著預先選定的組合。

它可方便內部人員從 Confluence 等位置發起工作。S09

目前文件規定，這種建立工作項目的方式只提供給 admin、agent 及 Service Desk Team role 的 collaborator。它不是「取得網址的匿名訪客都能填」的公開問卷。

要提供客戶入口，應先考慮把表單附到 request type 的 portal 流程，並檢查客戶存取權限。分享連結前，用預定接收者身分驗證，不用管理員視角代替。S09

04.02.07 至 04.02.10 提交後的四種偏好

Keep this form open for edits 適合資料會陸續補齊的表單，例如活動還在籌備；它讓有適當存取資格的人能繼續編輯與重新提交，並不把表單公開給沒有權限的人。

Save a PDF version of this form each time it is resubmitted 是每次重新提交保存快照。當第二次更新場地，你可以保留不同提交版本的文件紀錄；PDF 是快照，不會隨著活表單後續修改自動更新，也不應假設它等同完整稽核或法規合規措施。

Lock this form once it is submitted so only admins can edit 適合希望一般使用者提交後不能任意改動的資料。鎖定表單狀態不同於關閉整張工作項目：案件還可以繼續處理。具體表單操作要按狀態與管理權限判斷。

Show this form as recommended when selecting from a list of existing forms 是選單中的推薦顯示，方便 agent 挑表單；它本身不會自動附加、發送或提交表單。S05

這四項各回答不同問題：能否再編輯、是否留存快照、誰能在提交後修改、挑選時如何呈現。設計時先寫出業務目的，再測你選的組合；不要假定相互衝突的設定都能同時生效。當前文件另有「忽略欄位驗證」偏好，屬本課考綱外延伸；本課練習不啟用它，避免掩蓋資料缺漏。

隔離練習 會議準備表

前提：只有虛構資料、獲准的測試專案、測試 customer 與 agent。預先由管理員提供合適的 Jira 日期欄位。不要在正式專案更改共用欄位，也不把會議密碼、帳密或真實員工資料放進示例。

  1. 建立「練習：會議準備」form，寫用途與填寫說明，再加入活動方式、活動日期、補充說明。另寫「不要填入密碼」提醒。
  2. 把活動方式分成線上、實體，建立各自的條件區段；共同必填資訊留在始終可見的位置。Preview 逐一切換答案，觀察區段。
  3. 在支援的欄位測試預設回答；觀察使用者是否能修改，以及改值後條件區段是否跟著變。
  4. 將活動日期連到預先準備的同型別 Jira 欄位。確認 request form 沒有重複要求同一資料。
  5. 把 form 附到「練習：申請會議設備」request type。以測試 customer 提交，再由 agent 比較 Attached forms 與底層 Jira 日期欄位。
  6. 加入一個可用的第二語言，翻譯並啟用供客戶使用；使用兩種語言身分各測一次。若選項不能翻譯，記錄官方限制，不寫成翻譯成功。
  7. 在另一張測試工作項目手動 Attach form，先查看 Internal，再於確定無敏感資料時改為 External，觀察 customer 看到的差異。
  8. 在獨立測試副本分別試「保持開放＋重新提交 PDF」與「提交後鎖定」，不要在同一份紀錄混測。比較一般使用者與管理員的編輯能力。
  9. 產生只供測試內部角色使用的 shareable link，驗證適格角色可進入；不能以連結可複製就判定公開可用。

驗證狀態：以上為文件支持的練習設計，未在租戶實測。Default response 的型別差異、翻譯限制及偏好組合，必須以測試站結果補充，不能以教材示意圖當實測證據。

自我檢查

  1. 要讓「活動日期」能供一般 JQL 篩選，只建立同名 form field 足夠嗎？
  2. Recommended 偏好會自動把表單加到新工作項目嗎？

自我檢查

  1. 要讓「活動日期」能供一般 JQL 篩選，只建立同名 form field 足夠嗎？
  2. Recommended 偏好會自動把表單加到新工作項目嗎？
  3. 一個 shareable form link 可以直接當匿名顧客問卷嗎？
查看答案與理由
  1. 不足夠；應連到型別適合、可用的 Jira field，再驗證實際資料。
  2. 不會；它影響挑選既有表單時的推薦呈現。
  3. 不行。這種連結的建立方式有內部角色限制；一般顧客使用附到 request type 的入口流程較符合本課用途。

摘要

先設計問題及條件區段，再決定需要連到 Jira 的核心資料。表單位置、可見性、語言與提交後偏好分開檢查，才能同時滿足顧客填寫與團隊處理需求。

常見陷阱

  • 同名 form field 被誤認為已連上 Jira field
  • 把必填欄位藏進條件區段
  • 把 Internal 表單預期成客戶已可填寫
  • 把 shareable 理解成任何人都可存取
  • 把 PDF 快照、表單鎖定或推薦呈現誤認為工作流程完成

觀念釐清

Request form 是客戶入口的完整填寫畫面，Form 是可附加且有自己欄位與狀態的表單。Automation 附表到一張 work item，與管理員把表單配置到某個 request type，是兩件不同的事。

在 form 的 Settings 開啟 Create a shareable link，選定 request type，複製可用連結。General link 可讓有權限的人選擇服務專案、request type 與 form；Direct link 帶著預先選定的組合。

它可方便內部人員從 Confluence 等位置發起工作。S09

目前文件規定，這種建立工作項目的方式只提供給 admin、agent 及 Service Desk Team role 的 collaborator。它不是「取得網址的匿名訪客都能填」的公開問卷。

要提供客戶入口，應先考慮把表單附到 request type 的 portal 流程，並檢查客戶存取權限。分享連結前，用預定接收者身分驗證，不用管理員視角代替。S09
