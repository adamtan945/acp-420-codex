用一個例子理解

教學 Laptop 類型有 LAB-101、LAB-102。兩張假報修單都選 LAB-101，就應引用同一個物件 key；LAB-102 不應因此被引用。位置和狀態屬物件資料，故障描述屬工作項目資料。

03.01 在請求中使用 Assets

適用範圍、版本用語與案例前提

本課適用 Jira Service Management Cloud，以 company-managed 服務專案為主要情境。新版文件可能寫 service space、work item、work type；考綱仍使用 project、issue、issue type。

教材保留兩套名稱，不把新名稱直接代入 JQL。所有人物、工單和設定數值都是原創教學案例。

為什麼工單只寫「電腦壞了」不夠？

Agent 收到「電腦不能用」，往往還要問是哪一台、在哪裡、由誰使用、是否和別張故障單有關。Assets 讓這些資料成為可參照的物件，工作項目只需要連到正確物件，就能讀取相關脈絡。

它既可以記錄筆電、印表機等資產，也可以記錄伺服器、應用程式或其他需要理解關係的組態項目（configuration item，CI）。

官方來源：What are object schemas?

官方來源：asset-objects

本目標的邊界非常重要：ACP-420 03.01 要求使用已有的 schema、object type、object、attribute，以及把 Assets 欄位用於請求情境；不要求從零設計或配置 schema。以下假設 Assets 管理員已提供乾淨的教學資料。

不建立 schema、不設計匯入器、不連接資產探索工具；那些是考綱外的進一步管理工作。

目前官方 Assets 文件標示 Service Collection 的 Standard、Premium、Enterprise 付費方案包含 Assets。不能沿用舊資料的「一定僅 Premium／Enterprise」作為目前通則。是否有可用額度、完整入口和教學權限，仍要在實際方案確認；

本課不寫死配額或價格。

官方來源：What are object schemas?

03.01.01 四層名詞，先用一組例子記住

物件結構綱要（object schema）是相關資料的集合，像「教學設備資料庫」。它包含各種物件類型、物件、屬性、關係與自己的權限。物件類型（object type）集合相似事物，例如「筆電」「印表機」「位置」；同類物件共享可記錄的屬性結構。

官方來源：What are object schemas?

官方來源：asset-types

物件（object）是唯一一筆具體項目，例如「教學筆電 LAB-101」。屬性（attribute）則是這筆物件的細節，例如狀態、型號、所在位置或關聯物件。請注意「筆電」是種類，LAB-101 是個體；「位置」是屬性名稱，「教學北館」是這筆物件在該屬性上的值。

官方來源：asset-objects

官方來源：asset-attributes

用現成資料閱讀：在 Assets 開啟教學 schema，選「筆電」類型，找到 LAB-101，讀取其狀態與位置。若「位置」是參照另一個 object 的屬性，可循該關係看教學北館的詳細資訊。這是在使用既有模型，不是在替所有筆電新增新的 schema 欄位。

需要更新資料值時，仍應確認你有該物件的編輯權限和維護責任；本課主要練習查看及連結。

有關係不代表必然有因果。假設兩台筆電都參照同一個教學網路設備，這個脈絡可提示 agent 查共用因素；仍要有實際證據才判斷該設備是根因。Assets 是支援調查的資料來源，不會僅因畫出連線就自動證明故障原因。

03.01.02 Assets 自訂欄位把工單連到物件

Assets object custom field 是工作項目上的欄位，值是 Assets 物件的參照。選取 LAB-101 後，agent 可從工作項目開啟該物件；物件端也能看到相關工作項目。因此兩張工單連到同一台筆電，不是把資產資料複製成兩台。

官方來源：asset-field-about

欄位可用在 request type 的 request form，讓客戶從允許的候選物件中選擇；也可放在 agent 的 work item view。前提是欄位已由有權管理員建立並配置到適用範圍，且支援該專案與畫面。

Space admin 在 Request types 選擇教學類型後，將既有欄位加入表單或工作畫面，再用測試客戶驗證。

官方來源：asset-field-use

官方來源：request-customize

候選物件不是任意自由文字。管理員可透過 object schema、Filter scope（AQL）及 Filter work scope（AQL）限定它。AQL（Assets Query Language）找的是 Assets 物件；JQL 找的是 Jira 工作項目。

前者可根據物件屬性篩選，後者可透過 Assets 欄位間接找相關工單。本課只讀既有欄位的範圍、學會判斷為何某物件沒有出現，不修改 schema 或複雜 AQL 配置。

官方來源：Configure an Assets object custom field

官方來源：asset-jql

在 Forms 中使用，先確認資料到底存在哪裡

核對儲存位置和欄位型別，不能只比對文字是否相同。

Request form 是請求類型的客戶提交畫面；Forms 是可附加的結構化表單功能。兩者不是同一個東西。Jira 欄位可以和 Forms 欄位連結，但需型別相容、同一表單不能重複連到同一 Jira 欄位，也不應讓同一 Jira 欄位在 request form 和附加 Forms 重複出現。

官方來源：form-fields

官方來源：Link a form field to a Jira field

若教學租戶在 Forms 提供相容的 Assets 欄位或已配置的連結，選擇既有的「教學設備」並驗證提交後實際寫入哪個 Jira Assets 欄位；不要把普通文字欄「設備名稱」當成真正的 object 參照。

官方 Cloud KB 展示 Forms 與 Assets 欄位可共同存在，但不同表單編輯器及產品的可選欄位需現場確認。沒有相容入口時，可把既有 Assets Jira 欄位放在 request form，讓附加 Forms 收集症狀；不能因此宣稱 Forms 內連結已測試成功。

官方來源：forms-assets

官方來源：asset-field-use

在 queue 中使用：查工單，不是直接列資產清冊

要找與某類 Assets 有關的請求，可把既有 Assets 欄位加入適用的 queue 顯示欄，並使用該欄位的支援查詢。較進一步的範例為 "教學設備" IN aqlFunction("objectType = Laptop")，表示找出 Assets 欄位指向 Laptop 物件的工作項目；

其中 Laptop 必須是教學 schema 已存在的精確系統名稱。外層仍是 JQL，內層才是 AQL。

官方來源：asset-jql

這個範例不會列出所有沒被工單引用的筆電，也不會替缺漏資產建立資料。另需注意，官方指出 Cloud 的 Assets object field 不能用來排序 JQL 結果；可用其他支援欄位排序，不要反覆改 Assets schema 來解決不支援的 ORDER BY。

官方來源：asset-field-about

隔離練習：讓兩張報修單連到同一台教學筆電

前提：獨立教學專案與測試客戶、agent、space admin；管理員已提供教學 schema、Laptop 物件類型、LAB-101／LAB-102 物件，以及只含無敏感資料的「教學設備」Assets 自訂欄位。沒有這些先備資料時只做紙上辨識，不自行擴張到 schema 配置。

  1. 開啟現成 schema，指認 schema、type、object、attribute 四個層級。讀出 LAB-101 的狀態與位置，不改資料結構
  2. Space admin 在教學 request type 中加入既有「教學設備」欄位並設定清楚的顯示說明，例如「請選擇本次需要協助的教學設備」
  3. 使用獨立 customer 帳號打開 portal，記錄可看見哪些物件及哪些屬性。確認沒有不應對客戶公開的資料；不要把管理員看得到的全集當成客戶應看見的範圍
  4. 提交「教學：無法開機」，選 LAB-101；再提交「教學：電池充電異常」，同樣選 LAB-101。Agent 開啟兩單，核對都連到同一物件
  5. 從 LAB-101 物件端查看 Connected Jira work items，預期看見兩張有權限查看的教學工作項目。LAB-102 不應因此被誤連
  6. 若附加 Forms 已存在，核對症狀資料與 Assets 參照的儲存位置；在相容欄位可選時才測連結。提交後從工作項目實際欄位讀值，不只看表單文字
  7. 建立或編輯一個教學 queue，篩出引用此類設備的測試請求；預期有兩張 LAB-101 相關單。另以一張未選設備的請求做反向驗證

設定後最重要的可觀察結果，是工單與正確物件的連結及適當資訊可見性。看到「LAB-101」文字不一定代表連結成功，要試著開啟物件並核對 object key。

官方來源：asset-field-use

官方來源：asset-field-about

官方來源：asset-jql

排錯：物件清單空白時先問哪一層

先確認已有那筆物件且它位於預期 schema；再檢查既有自訂欄位是否指向正確 schema，以及 AQL 篩選是否排除了它；接著核對目前工單欄位值是否影響 Filter work scope；最後用正確帳號測試物件／欄位可見性。不要為了解決空清單直接把全 schema 公開給所有人。

重點回顧

用 schema→type→object→attribute 辨識資料層級，再用 Assets 自訂欄位把請求連到具體物件。分清 JQL 查工單、AQL 查物件，以及 request form 和 Forms 的儲存行為。

常見陷阱

  • 同名文字不等於同一個 object 參照
  • 能看工單不代表應公開整個資產資料集合
  • 不能用 Cloud Assets 欄位直接排序 JQL 結果
  • 舊文件的 Premium-only 說法不能取代目前 Service Collection 方案查核

觀念釐清

03.01 的「使用」包含讀取物件脈絡、選擇既有欄位、理解關聯與查詢；建 schema、資料匯入或自動改寫物件不是本目標要求。第 08 領域的 Assets automation 另有自己的考綱範圍。

文件限制與待實機核對

Forms 內的 Assets 選項與 linked-field 型別相容性未在租戶測試；本課提供已確認的 request-form 路徑與檢查方式，不保證每一版 Forms builder 有相同控制項。

任何 display name／system Name 分離的 Beta 功能均屬目前產品延伸，本課查詢以實際系統名稱核對。
